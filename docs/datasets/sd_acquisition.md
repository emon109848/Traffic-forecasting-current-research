## Local traffic-array inspection

The user downloaded flowsd.npz from the author-linked folder and placed it at
`data/raw/largest_sd/flowsd.npz`. The original was inspected without modification
using NumPy with allow_pickle=False. File size is 200,709,382 bytes (191.4 MiB).
It contains one data array, float64, shape (35,040, 716, 1). No timestamps, sensor
IDs, masks or other arrays are included. The shape matches the expected SD
benchmark but does not independently verify dates or temporal cadence.

All 25,088,640 values are finite and nonnegative, with range 0–999 and mean
244.3096. There are 563,841 zeros (approximately 2.2474%). No sensor is entirely
zero; four frames are zero across all sensors. These are audit findings, not
proof that all zero readings are missing. Preserve zeros until a documented
validity policy is chosen. See sd_array_audit.json for indices and SHA-256.

At that stage, the next inspection step was to obtain sd_meta.csv
from the author repository, establish sensor-order provenance and investigate
timestamp/missingness evidence. Do not invent timestamps or silently map NPZ
columns to metadata row order. No preprocessing or training has been performed.

## Local metadata inspection

sd_meta.csv was supplied locally by the user from the author repository. It is
47,979 bytes with 716 rows matching the traffic sensor axis. All 716 sensor IDs
and ID2 values are unique. ID2 runs contiguously in row order from 6931 to 7646;
these are source-network indices, not zero-based SD array columns. Keep row order
unchanged and do not use ID2 directly to index the 716-column array.

Every row is District 11 / San Diego. Coordinates are finite and within valid
bounds, with no duplicate coordinate pairs. Latitude spans 32.544296–33.406738;
longitude spans -117.591561–-116.880704. No empty fields were found in the ten
metadata columns. See sd_metadata_audit.json for checksum and detailed findings.

Both artifacts are structurally consistent with the intended SD benchmark.
However, the NPZ has no embedded sensor IDs, so row-to-column alignment is an
author-artifact provenance assumption, not independently verified. No sorting
or reordering has been applied. Original timestamps and validity flags cannot
be recovered from these two files alone. The four all-zero frames are indices
6536–6539; their cause and calendar time remain unknown. Dataset terms and an
immutable source revision also remain unresolved.

The user subsequently approved proceeding with this processed benchmark and
documented assumptions. Calendar reconstruction and zero handling are protocol
choices, not observed facts. The shared pipeline and simple baselines are now
complete; obtaining original timestamp-bearing data is deferred.
